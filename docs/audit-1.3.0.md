# 1.3.0 改动审查与发布验证

日期：2026-10-25。范围为 `v1.2.0` 之后的提交，以及本次发布前工作区中尚未提交的改动，重点检查搜索配置、主观题答案和图片准备流程。

## 审查发现与修复

| 触发方式 | 原问题 | 修复 |
| --- | --- | --- |
| 主观题以 `[1]` 编号或数学集合开头 | 被当作无效 JSON，整份答案丢失 | 区分编号正文与结构化响应，继续拒绝缺少答案的 JSON |
| 主观题直接返回带围栏的程序代码，代码含 `###` | 代码围栏提前被剥离，字面量被当作分隔符改成换行 | 答案工作流接收原始响应，仅拆除 JSON 对象的外层围栏，保留代码围栏和字面量 |
| 图片下载完成后，解码或缩放一直没有完成 | 计时器虽然触发，但不能结束准备阶段的等待 | 图片准备的完整异步过程受取消信号和超时约束，超时后不再提交模型 |
| 图片题多次重试，答题后还需总结 | 后端绝对等待预算未包含各次图片准备时间 | 为答题和总结的每次尝试计入最多 30 秒的图片准备预算 |
| 答题或总结模型超时 | 误按用户取消处理；总结超时可能跳过已有答案回退 | 仅用户取消终止工作流，其他超时按模型失败处理并保留回退行为 |

前三类及等待预算均有新增回归测试。实际桌面程序进一步验证基础模型超时、总结超时回退，以及解码挂起时的图片准备超时。

## 本版包含的功能

- Firecrawl、Exa、DeepSeek 分别保存并恢复 Key、服务地址和代理配置。
- Exa 新增 `lite`，保留其他模式及旧配置；设置页按服务展示参数，并可直接测试搜索。
- 问答、简答、论述、计算等主观题保留小问编号、顺序和段落；多选和多空继续使用 `###`。
- 图片题要求全部图片就绪后才提交模型，失败链接最多重试三次。
- 包含此前已提交的 macOS 构建与窗口恢复调整；本次发布产物和运行验证仅覆盖 Windows x64。

Exa 请求参数与模式兼容性按 [Search API 官方文档](https://exa.ai/docs/reference/search)核对；界面费率按 [官方价格](https://exa.ai/pricing)核对。自动化搜索测试使用本地模拟服务，未使用真实付费密钥。
