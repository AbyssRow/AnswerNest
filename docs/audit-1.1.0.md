# 1.1.0 功能审计与回归记录

日期：2026-10-17。范围为桌面题库、导入、配置保存、模型选择、答题流程和 OCS 接口中的功能错误。

## 本次修复

| 触发方式 | 原问题 | 修复 |
| --- | --- | --- |
| 导入包含逗号、双引号或换行的 CSV | 简单按逗号和换行切分，题目与答案错列 | 使用表格解析器处理 CSV 引号和多行单元格 |
| 导入答案为数字 `0`、布尔值的 XLSX | `0` 被空值判断丢弃，非字符串值传入题库 | 统一转换为文本，保留零和文本编号 |
| 展示含 `<div>`、`x<2` 的题目，或搜索 `C++` | 题目内容被当作 HTML；高亮影响原文 | 先匹配原文，再转义各段，仅插入高亮标记 |
| 快速切换目录、翻页或改变搜索词 | 先发出的慢请求覆盖后发出的结果 | 用请求序号丢弃过期响应 |
| 首页自动入库后切换到题库页 | 已挂载的题库仍显示旧列表和数量 | 进入题库页时刷新目录和当前列表 |
| 添加平台、修改全局模型设置后恢复默认 | 浅拷贝污染默认配置，恢复默认仍留下旧值 | 每次创建独立的默认配置 |
| 禁用或删除已选模型 | 答题或总结选择仍可能指向失效模型 | 修改后统一清理选中状态 |
| 模型本地缓存损坏、导入较旧配置 | 没有从文件恢复；嵌套默认字段缺失 | 损坏缓存触发文件恢复，导入补齐默认字段 |
| 连续修改设置并立即执行依赖设置的操作 | 保存 Promise 提前完成；并发写入争用同一临时文件 | 等待文件写入、按顺序保存快照，后端串行替换文件 |
| 用户实际目录与按用户名拼出的路径不一致 | 数据库定位到错误的 `C:\Users` 路径 | 统一使用 `%LOCALAPPDATA%`，缺失时使用 `%USERPROFILE%` |
| 程序目录不可写，或更新后需保留配置 | 配置保存在 exe 同级目录，依赖该目录写权限 | 配置存入用户数据目录，首次读取时复制旧配置并保留原件 |
| 刷新 WebView 界面 | 恢复接口读取已停用的日志表；前端丢弃请求正文 | 从当前进程内存恢复请求记录并保留完整显示字段 |
| 服务正在运行时配置端口与实际端口不同 | 复制出的 OCS 配置可能指向错误端口 | 运行中使用服务实际端口 |

请求详情仍只保存在当前进程内存中；退出应用后不会恢复上一进程的请求详情。每日请求计数继续保存在数据库。

## 验证

- `npm run test:model-api`：60 项通过，包含新增 CSV、XLSX、显示高亮、模型配置、保存顺序和失败重试回归测试。
- `cargo test --manifest-path src-tauri/Cargo.toml --lib`：23 项通过，包含数据目录定位、旧配置迁移和 16 路并发配置写入测试。
- `npm run tauri:build:win`：类型检查、前端构建、Rust release 编译及 Windows x64 NSIS 安装器打包。
- 实际 Windows 桌面程序使用隔离的数据目录和 WebView2 测试，9 组场景通过，无页面脚本异常。验证旧配置复制、自定义数据目录、目录与题目编辑、清空选项、零答案、服务启动与停止、HTML 原文显示、目录自动刷新、慢响应不能覆盖后续目录选择、界面重载后恢复本次会话记录、清空记录，以及模型缓存损坏后从文件恢复并成功答题。
- 使用用户提供的 [OCS 脚本](https://cdn.ocsjs.com/ocs.user.js)，本次下载版本为 **5.2.1**，调用其中实际的 `defaultAnswerWrapperHandler`，连接实际桌面 HTTP 服务。验证 HEAD 探测、自定义端口、题干与选项优化字段、Base64 图片、两个答题模型分歧后总结，以及重复题命中本地缓存。

AI 接口使用本地模拟响应，避免消耗真实账号额度。本次未逐一实测所有真实 AI 提供商，也未在具体网课网站上执行完整 OCS 用户脚本；发布产物为 Windows x64 安装包。

构建仍有已有的前端大分块提示；不影响本次类型检查与构建通过。没有为本次审计升级项目依赖。
